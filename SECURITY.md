# Безопасность

Sentinel стоит между инженером и серверами клиентов, поэтому к уязвимостям относимся серьёзно.

**Не публикуйте уязвимость в открытом Issue.** Сообщите через [приватный отчёт GitHub](https://github.com/cefiro777/sentinel-monitor/security/advisories/new)
(вкладка Security → Report a vulnerability): что уязвимо, как воспроизвести, версия. Ответ — в течение нескольких дней, исправление выходит отдельным релизом.

## Как устроена защита

- Агент сам подключается к серверу по HTTPS; входящих портов у клиента нет. Опционально — pin сертификата сервера.
- Каждый запрос агента подписан HMAC-SHA256 (секрет агента хранится под DPAPI); регистрация — одноразовым токеном с ограниченным сроком.
- Команды сервера агенту и пакеты обновления подписаны Ed25519; агент выполняет только команды из **локального** белого списка,
  который с сервера изменить нельзя (`SentinelAgent.exe allow`).
- Удалённые действия в дашборде требуют второго фактора (TOTP). Пароли — Argon2id, секреты в БД (пароли устройств, токены облаков) — AES-GCM.
- Роли: администратор, инженер, клиент (видит только свои серверы); все действия пишутся в аудит.

Ключи сервера (`keys/data.key`, `keys/signing.key`, `keys/jwt.key`) — самое ценное: храните бэкапы ключей отдельно и под доступом только администраторов.
