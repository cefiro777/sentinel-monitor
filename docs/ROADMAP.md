# Дорожная карта

Каждый этап заканчивается работающим вертикальным срезом: агент → сервер → дашборд → оповещение.

## Этап 0 — Каркас (фундамент) ✅
- [x] Solution, проекты, общие настройки сборки (CPM)
- [x] `Contracts`: DTO протокола, `CheckResult`, `CommandEnvelope`, HMAC-подпись
- [x] `Agent`: служба Windows, enrollment, хранение секрета (DPAPI), heartbeat, получение конфига, планировщик модулей, офлайн-буфер (SQLite)
- [x] `Server`: PostgreSQL + EF Core миграции, agent API, SignalR-хаб, JWT для пользователей, аудит
- [x] `Web`: логин, обзор клиентов/хостов, страница хоста, токены регистрации, пользователи
- [x] `deploy`: docker-compose (server + postgres + caddy для TLS)
- [x] Модуль `system` (CPU, RAM, аптайм, pending reboot, дрейф часов) как первый end-to-end пример
- [x] Команды с подписью Ed25519 и белым списком на агенте (ping, config.refresh, service.*, reboot) — раньше плана
- [ ] CI-скрипт сборки

## Этап 3 — Бэкапы ✅ (MS SQL, PostgreSQL и Яндекс.Диск — код готов, проверены в бою не были)
- [x] Общий конвейер заданий: расписание (ежедневно/по дням/каждые N ч), назначение (папка/шара с учёткой), sha256, ретеншн по наборам, облако, отчёт в BackupRun
- [x] `backup.files` — полный/разностный zip, исключения, VSS через WMI с откатом на живой том, проверка архива
- [x] `backup.1c.file` — 1Cv8.1CD через VSS, проверка заголовка базы
- [x] `backup.mssql` — BACKUP DATABASE full/diff, VERIFYONLY, откат без COMPRESSION для Express (не проверен: нет SQL Server)
- [x] `backup.postgres` — pg_dump -Fc + pg_restore --list, автопоиск bin (не проверен: нет клиентских утилит)
- [x] Яндекс.Диск: загрузка потоком, сверка sha256/размера, ретеншн в облаке (в корзину), квота (не проверен: нет токена)
- [x] Секреты в настройках модулей (пароли, токены) шифруются в БД, маскируются в API, раскрываются только агенту
- [x] Dead man's switch: инцидент «бэкап просрочен» при отсутствии успешного запуска дольше 1.5 периода, автозакрытие
- [x] Страница «Бэкапы»: матрица заданий (локально/облако/просрочен), история запусков с логом, «Запустить сейчас»
- [ ] Цель S3 / WebDAV — по потребности

## Этап 4 — Видеонаблюдение ✅ (проверено на эмуляторах API; на реальных регистраторах — предстоит)
- [x] `cctv.rtsp` — собственный RTSP-клиент: DESCRIBE/SETUP/PLAY, Basic/Digest, ожидание реального RTP-пакета, таймауты
- [x] `cctv.onvif` — SOAP с WS-UsernameToken: время (дрейф), модель, профили, RTSP-потоки профилей
- [x] `cctv.hikvision` — ISAPI: deviceInfo, время, HDD, IP/аналоговые каналы, поиск записей за окно по каждому каналу
- [x] `cctv.dahua` — CGI: системная информация, время, HDD, состояние каналов NVR, mediaFileFind за окно
- [x] Команды `cctv.settime` (время агента → регистратор) и `cctv.reboot` для Hikvision/Dahua, только из MFA-сессии
- [x] Страница «Видеонаблюдение»: устройства со светофором, дрейф часов, панель с каналами/дисками/проблемами
- [x] Пароли устройств и в RTSP-URL шифруются в БД; при перенастройке проверки старые состояния и инциденты сбрасываются
- [ ] Снимок кадра с камеры для превью в дашборде — по потребности
